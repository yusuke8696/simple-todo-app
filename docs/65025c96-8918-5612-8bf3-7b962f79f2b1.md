# 構成設計

## 構成概要

本プロジェクトは、個人用ToDo管理アプリの動作確認用プロトタイプを構築するものである。

- **プラットフォーム**: PCのWebブラウザ（Chrome・Edge）
- **技術スタック**: HTML, CSS, JavaScript (Vanilla)
- **データ永続化**: ブラウザの `localStorage`
- **実装ファイル**: `index.html` (単一ファイル構成)

## 構成要素

単一ファイル `index.html` 内に以下の要素を配置する。

1. **入力エリア**
   - タスク名を入力するための `<input type="text">`。
   - 追加ボタン（`<button>`）。
2. **一覧エリア**
   - 登録されたタスクをリスト形式で表示する `<ul>`。
   - 各リスト項目（`<li>`）には、チェックボックス、タスク名（完了時は `<del>` タグで囲む）、削除ボタンを配置する。
3. **制御ロジック**
   - DOM要素の取得とイベントリスナーの登録。
   - `localStorage` への読み書き処理。
   - 入力バリデーション（空文字・空白のみ、100文字制限）。
   - 完了状態の切り替えと削除確認ダイアログの表示処理。

## データと連携

- **永続化**: `localStorage` キー `"todos"` にタスク配列をJSON文字列として保存・読み出す。
- **同期**: ページ読み込み時に `localStorage` からデータを取得し、一覧を再構築する。
- **変更**: 追加・完了切り替え・削除の各操作で、変更後の配列を `localStorage` に書き戻す。

## 制約と未決事項

- 編集機能、期限管理、優先度、カテゴリ、リマインダー、ログイン、複数人共有は実装しない（要件定義で対象外）。
- 外部ライブラリや依存パッケージは使用しない（単一ファイル構成のため）。
- セキュリティ上、ユーザー入力を信頼せず、追加前に文字列長と空白チェックを行う。
- 完了状態の切り替えはユーザーの操作（チェックボックス）のみで制御する。
- 削除は確認ダイアログを表示した後に実行し、キャンセル時は元データを保持する。
